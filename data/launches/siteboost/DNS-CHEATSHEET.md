# SiteBoost DNS Cheatsheet — Email Deliverability Records

Paste these into your DNS provider (Cloudflare, Namecheap, Google Domains, etc.)
for the new outbound domain (e.g. `hello.wheellsverse.com`). All values must match exactly.

**Why this matters**: Without SPF + DKIM + DMARC properly set, your cold emails
land in spam and your domain's reputation tanks within 5-7 days. Spend 15 minutes
on this NOW, save weeks of pain later.

---

## 1. MX Records (receiving email)

If using Google Workspace ($6/user/mo):

| Type | Host/Name | Value | Priority | TTL |
|---|---|---|---|---|
| MX | @ | `smtp.google.com.` | 1 | 3600 |

If using a different provider (Zoho, Fastmail), use their MX values instead.

---

## 2. SPF (Sender Policy Framework — authorizes who can send AS your domain)

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| TXT | @ | `v=spf1 include:_spf.google.com include:sendgrid.net include:instantly.ai -all` | 3600 |

**Notes**:
- `include:_spf.google.com` — if using Google Workspace for inbox
- `include:sendgrid.net` — if using SendGrid for transactional emails (Stripe receipts, etc.)
- `include:instantly.ai` — if using Instantly.ai for cold outbound. **Required for SiteBoost.**
- `-all` = strict mode (recommended). Anything not in the include list = REJECTED.

Replace any existing SPF record. **DO NOT add a second TXT record starting with `v=spf1`** — multiple SPF records = invalid SPF = mail goes to spam.

### Verify SPF

```bash
dig TXT hello.wheellsverse.com | grep spf
# or
nslookup -type=TXT hello.wheellsverse.com
```

Expected: one TXT record starting with `v=spf1` containing the includes above.

## 3. DKIM (DomainKeys Identified Mail — cryptographic signing)

DKIM keys are generated by each email provider. You'll need to add ONE DKIM record per provider:

### Google Workspace DKIM

1. Go to [admin.google.com](https://admin.google.com) → Apps → Google Workspace → Gmail → Authenticate email
2. Click "Generate new record" → 2048-bit
3. Copy the TXT record value Google shows you
4. Paste into DNS:

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| TXT | `google._domainkey` | `v=DKIM1; k=rsa; p=...` (the long value Google gives) | 3600 |

5. Wait 48 hours for DNS propagation, then go back to admin.google.com and click **Start authentication**.

### Instantly.ai DKIM

1. In Instantly → Email Accounts → Add your inbox (e.g. `jay@hello.wheellsverse.com`)
2. Instantly's setup wizard will show you 3 DNS records to add (DKIM + return-path + Custom Tracking)
3. Add all 3 exactly as shown. Typical pattern:

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| TXT | `instantly._domainkey` | `v=DKIM1; k=rsa; p=...` | 3600 |
| CNAME | `em.hello.wheellsverse.com` | `instantly-tracking.com` | 3600 |
| TXT | `_dmarc` | (already covered below) | 3600 |

### SendGrid DKIM (if used)

If you use SendGrid for transactional emails (Stripe receipts, intake confirmations):

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| CNAME | `s1._domainkey` | `s1.domainkey.uxxxxx.wlxxx.sendgrid.net` | 3600 |
| CNAME | `s2._domainkey` | `s2.domainkey.uxxxxx.wlxxx.sendgrid.net` | 3600 |

SendGrid → Settings → Sender Authentication → Domain Authentication walks you through this.

## 4. DMARC (Domain-based Message Authentication, Reporting and Conformance)

This tells receivers what to do with mail that fails SPF/DKIM:

### Start cautious (recommended for first 30 days)

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc-reports@hello.wheellsverse.com; pct=100; adkim=r; aspf=r` | 3600 |

`p=none` = monitor only, don't reject anything. You'll get daily reports at `dmarc-reports@hello.wheellsverse.com` showing what's passing/failing.

### After 30 days of clean reports — tighten to quarantine

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| TXT | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@hello.wheellsverse.com; pct=100; adkim=s; aspf=s` | 3600 |

`p=quarantine` = failing mail goes to spam folder (not rejected outright).

### After 90 days clean — tighten to reject (full enforcement)

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| TXT | `_dmarc` | `v=DMARC1; p=reject; rua=mailto:dmarc-reports@hello.wheellsverse.com; pct=100; adkim=s; aspf=s` | 3600 |

`p=reject` = failing mail is bounced. Maximum protection against spoofing.

**DON'T jump straight to `p=reject`** — start with `p=none`, watch reports for 30 days, then progress.

## 5. MTA-STS (optional but improves deliverability score)

Tells receiving servers to require TLS when sending to your domain.

| Type | Host/Name | Value | TTL |
|---|---|---|---|
| TXT | `_mta-sts` | `v=STSv1; id=20260603T120000Z` | 3600 |

You'll also need to host a policy file at `https://mta-sts.hello.wheellsverse.com/.well-known/mta-sts.txt` containing:

```
version: STSv1
mode: enforce
mx: smtp.google.com
max_age: 86400
```

Skip this if you're not comfortable with the extra setup — SPF+DKIM+DMARC alone covers 95% of deliverability.

## 6. Verify everything works

After all DNS records are added (wait 5-10 min for propagation):

### MXToolbox (web)
1. Go to [mxtoolbox.com/SuperTool.aspx](https://mxtoolbox.com/SuperTool.aspx)
2. Run these checks for `hello.wheellsverse.com`:
   - SPF Record Lookup → should show your SPF without errors
   - DKIM Lookup → enter selector `google` → should resolve
   - DMARC Lookup → should show your policy
   - Blacklist Check → must be CLEAN. If listed on any blacklist, you bought a poisoned domain. Get a refund and try another.

### Command-line verification

```bash
# SPF
dig TXT hello.wheellsverse.com | grep spf

# DKIM (for Google Workspace)
dig TXT google._domainkey.hello.wheellsverse.com

# DMARC
dig TXT _dmarc.hello.wheellsverse.com
```

All three should return non-empty values matching what you set above.

### Send a test email

Send a test from `jay@hello.wheellsverse.com` to `check-auth@verifier.port25.com` — they'll
reply within 60 seconds with a full SPF/DKIM/DMARC report. Aim for "PASS" on all three.

Also send a test to a Gmail address and check the headers:
1. In Gmail, open the test email
2. Click ⋮ → "Show original"
3. Look for:
   - SPF: PASS
   - DKIM: PASS
   - DMARC: PASS

If any say FAIL, fix that record before sending real cold emails. **Sending with failing auth = instant spam folder forever**.

## 7. Domain warmup checklist (before first real cold send)

After DNS is set up, warm up the inbox over 14-28 days:

| Day | Send volume | What to send |
|---|---|---|
| 1-3 | 5/day | Genuine emails to people you know |
| 4-7 | 15/day | Mix: known contacts + Instantly warmup pool |
| 8-14 | 30/day | Mostly Instantly warmup + a few real customer/support emails |
| 15-21 | 50/day | Instantly warmup + small batches of real prospects |
| 22-28 | 75/day | Mostly real outbound + 30% Instantly warmup ongoing |
| 29+ | 100/day cap per inbox | Real outbound; keep 20% warmup running forever |

**NEVER exceed 100/day per inbox in the first 90 days.** New domains that suddenly send 200/day get insta-blacklisted. Use multiple inboxes (`jay@`, `hello@`, `team@`) to spread volume.

**Critical metric to watch**: Postmaster Tools spam rate. Stay under 0.1%. If it hits 0.3%, pause all sending and investigate.

## TL;DR — minimum viable setup

If you only do 4 things, do these (in order):

1. **MX records** for Google Workspace (or your mail provider)
2. **SPF**: `v=spf1 include:_spf.google.com include:instantly.ai -all`
3. **DKIM**: generate via Google admin + Instantly + paste into DNS
4. **DMARC**: `v=DMARC1; p=none; rua=mailto:dmarc-reports@hello.wheellsverse.com`

Send a test to `check-auth@verifier.port25.com`. If all 3 say PASS, you're good. Then start the 14-day warmup before your first cold send.

The other items (MTA-STS, BIMI, reverse DNS) are "nice to have" — skip them until you're sending 500+/day per inbox.
